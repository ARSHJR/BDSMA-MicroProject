# Thread — Fashion Product Recommender (SDG 12)

**Course:** Big Data and Social Media Analytics · **Category:** Recommendation system · **SDG 12:** Responsible consumption & production

A hybrid, explainable fashion recommender built on **real** data (Amazon Reviews 2023 – Fashion: 826k products, 2.5M reviews).
It recommends clothing, footwear and accessories from user preferences, product content, behavioural interactions and review-derived trends — and
nudges users toward **longer-lasting, more versatile purchases** with a transparent, user-adjustable sustainability weight.

## Features
| Area | What is implemented |
|---|---|
| Catalogue | 26,809 real products with images, brand, type, colour, price (when listed), search, 8 filters, 6 sorts, pagination, detail page, related items, wishlist |
| Recommender | Content (TF-IDF + attributes, cosine) · item-item collaborative filtering (shrunk cosine) · preference onboarding · Bayesian popularity prior · MMR diversification · per-item **explanations** |
| Personalisation | Likes/dislikes/views/wishlist stored per anonymous guest session; recommendations are recomputed by the backend on every change; cold start handled |
| Social/Big-data analytics | DuckDB streaming ingest of 2.5M reviews, VADER sentiment on 838k review texts, category trends over time, emerging categories & phrases, hashtag/sentiment analyser with **CSV import** and a clearly labelled **synthetic** social demo |
| SDG 12 | Longevity proxy (ratings + durability/fit-return/versatility review signals, shrunk by evidence), λ slider, own-before-buy warnings, longer-lasting alternatives, honest limitations |
| Dashboard | Products by category, price distribution, brands, sentiment, longevity distribution, evaluation, dataset counts — all computed from processed data |
| Evaluation | Chronological split, Precision/Recall/NDCG@10, coverage, diversity, latency, 5 baselines, bootstrap CI, sustainability trade-off |

## Datasets (see `/insights` page and `ARCHITECTURE.md`)
| Dataset | Source | Licence / use | Size used |
|---|---|---|---|
| Amazon Reviews 2023 – *Fashion* (metadata + reviews) | https://amazon-reviews-2023.github.io/ (McAuley Lab, UCSD) | Academic research use; cite Hou et al. 2024. Images are hot-linked, not redistributed | raw 826,108 products / 2,500,939 reviews → **26,809 products, 170,676 interactions, 70,813 users, 838,147 review texts** after cleaning + k-core |
| Synthetic social posts | generated by `pipeline/03_social.py` | **Synthetic**, labelled everywhere | 4,000 posts |

Why Amazon Fashion: it is the only openly downloadable (no login/API key) fashion dataset found that combines product text, images, **timestamped user–item interactions** and review text. H&M (Kaggle) needs credentials; Fashion-Product-Images has no interactions.
No credible open **fashion social-media** corpus (X/Instagram/TikTok APIs are closed; scraping avoided) was available, so *real* trends/sentiment come from **product reviews (user-generated content, not social posts)** and social-post analytics run on user-imported CSVs or the labelled synthetic demo. Nothing synthetic is presented as a finding.

### Cleaning decisions
* The source `categories` field is empty → product type / department / colour / material are **derived from title text with documented word-boundary rules** (`pipeline/taxonomy.py`); 6.5% remain "Other".
* Only **12% of products have a price** (3,235) — shown as “Price n/a”, never imputed.
* 55,420 duplicate listings (same title + brand) merged; duplicate user–item reviews collapsed; implausible prices/timestamps dropped; iterative k-core (users ≥ 2, items ≥ 3).

## Architecture (short)
`Raw JSONL.gz → DuckDB ingest/clean → Parquet → features, sentiment, sustainability proxy → similarity models + evaluation → FastAPI → React`. Details and Mermaid diagrams in [ARCHITECTURE.md](ARCHITECTURE.md).

**Stack:** Python 3.13, FastAPI, Pydantic v2, SQLAlchemy (SQLite; Supabase/Postgres via `DATABASE_URL`), DuckDB, pandas, scikit-learn, SciPy, VADER · React 19, Vite, TypeScript, Tailwind v4, Recharts.

## Install & run
Prerequisites: Python ≥ 3.11, Node ≥ 20, ~2 GB free RAM, ~1 GB disk.
```powershell
pip install -r requirements.txt
cd frontend; npm install; cd ..

# (A) processed data is already in data/processed + data/models  -> skip to (B).
# To rebuild everything from scratch (~25 min; downloads ~500 MB, no account needed):
./run_pipeline.ps1

# (B) start the app (two windows)
./start.ps1
#   API  http://127.0.0.1:8000/docs      App  http://localhost:5173
```
Manual: `cd backend; python -m uvicorn app.main:app --port 8000` and `cd frontend; npm run dev`.

### Supabase (optional)
Works out of the box with SQLite. To migrate: run `supabase/schema.sql` in the Supabase SQL editor, `pip install psycopg2-binary`, and set `DATABASE_URL=postgresql+psycopg2://…` in `.env` (see `.env.example`). ## Results (held-out chronological test, 5,926 users, K = 10)
| Model | P@10 | R@10 | NDCG@10 | Coverage | Diversity |
|---|---|---|---|---|---|
| Random | 0.0000 | 0.0003 | 0.0002 | 13.9% | 0.848 |
| Popularity (baseline) | 0.0029 | 0.0283 | 0.0181 | 0.0% | 0.819 |
| Content (TF-IDF cosine) | 0.0010 | 0.0090 | 0.0051 | 67.9% | 0.396 |
| Item-kNN CF | 0.0019 | 0.0179 | 0.0084 | 54.0% | 0.824 |
| SVD (64 factors) | 0.0001 | 0.0011 | 0.0005 | 62.3% | 0.836 |
| **Hybrid** (0.2 content, 0.2 CF, 0.3 pop; tuned on validation) | **0.0032** | **0.0310** | **0.0183** | 25.5% | 0.818 |

**Honest reading:** on >99.99%-sparse review data, popularity is a very strong baseline. The hybrid is *statistically indistinguishable* from it on NDCG (paired-bootstrap 95% CI of the difference [−0.0011, +0.0015]) but is **personalised and covers 25% of the catalogue** instead of recommending the same ~10 items to everyone; it clearly beats every pure model. 49.5% of test items never appeared in training (item cold start) — content signals cover those. Online latency (full pipeline with explanations): ~14 ms mean.
Sustainability trade-off (same lists): raising λ from 0 → 0.4 lifts average longevity score 61.5 → 65.7 with **no NDCG loss** (0.0183 → 0.0184); at λ = 0.8 accuracy collapses (0.0055).
Processing benchmark (per-product mean rating over 2.5M raw reviews): pandas chunked 55.5 s vs DuckDB 5.6 s (**9.9×**), peak RSS 351 MB vs 491 MB. Single machine only — no distributed processing is claimed.

## SDG 12 relevance
Fewer, longer-lived purchases reduce textile waste (target 12.5). The platform (1) ranks with a *longevity proxy* built from what reviewers say about durability, fit-related returns and versatility; (2) tells users when something resembles an item they already saved ("own before buy"); (3) offers higher-longevity alternatives; (4) puts the trade-off in the user's hands via a slider and explains every effect.

## Limitations
* The longevity score is a **heuristic proxy**, not an environmental measurement — no carbon, material-composition or certification data exists in the source and none is invented. The score uses review text from the whole period, so the λ trade-off table is descriptive, not a clean held-out result.
* Price available for only 12% of products; categories are keyword-derived (some errors).
* Amazon “users” are reviewers; interactions are ratings turned into implicit feedback; absolute accuracy figures are low by nature of the data.
* Social-media analysis of real posts requires a CSV you are licensed to use; the built-in social dataset is synthetic.
* Images are hot-linked from Amazon's CDN; broken links fall back to a placeholder.
* Visual QA was done in Chrome on desktop width; mobile layout is responsive by construction but was not exhaustively device-tested.

## Deferred / not done
Authentication (guest sessions only), image-based similarity, ALS/neural recommenders, real-time model retraining from live interactions (live interactions personalise via the item-neighbour profile; the neighbour matrices are rebuilt by the pipeline), Playwright end-to-end suite (API-level journeys and component tests are automated instead).
